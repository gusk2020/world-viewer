# Anti-KyTerra 統合地球儀（表示だけ）

`anti-kytera/globe/index.html`。1つの地球儀で 1岩盤 → 2海（海抜0 m）→ 3気温 → 4湿度 → 5降水 → 6陸氷 → 7植生（通年の潜在自然植生）を切り替えて見る。

- **新しい推定はしない。** 読むのは PR #12 の `results/display.json` + `fields.bin` と、植生（PR #13）の `veg/results/veg_display.json` + `veg_fields.bin` だけ。精度の改善、機能の追加、地名別・地域別の補正はしていない。
- **表示**：3〜7の段階は「モデル／教師／差」と「地球適合／地域保留」を切り替えられる。7植生の「差」は、一致・不一致の地図。
- **中央の値**：照準地点について、選んだ検証モードのモデル値と教師値（および差）を並べて出す。教師に値がない地点は「教師なし」。1・2の段階は入力データなので、教師はなし。
- **植生の重ね順**：氷（厚さ > 10 m。海面下の岩盤上も含む）＞ 海（岩盤 < 0 m）＞ 植生。氷の値は、6陸氷の段階の `H_{fit,holdout,teacher}` から取る（受け渡しデータの氷マスクと、全セルで一致を確認済み）。
- **地球適合と地域保留**：表示も数値も、選んだモードのものだけを出す。地球適合は学習した地球への当てはめで、実力の目安は地域保留。
- 数値と限界は `../STAGES.md` と `../veg/VEG.md` を参照。

## 描画の修正（極地の筋と解像度、2026-09-27）

**原因の切り分け**（北極・南極の両方で、同じ地点・同じ倍率の画像と、極を中心にした円周上の明るさの細かい変化量で比べた。値は画面上の平均）

| 候補 | 結果 |
| --- | --- |
| 元データ | 格子を直接、極投影で描くと、極の近くで淡い放射状の「くさび」がある。緯度経度格子では各行のセル数が同じなので、極の近くのセルは東西が南北より数百倍細い（0.25°格子の最終行では約450倍）。その細いセルの一つ一つが別々の平均値なので、並べると放射状に見える。地形の筋ではなく、格子の形が原因。 |
| 緯度経度の参照（陰影の計算） | **主因。** 東西の傾きを、隣の経度セルとの差 ÷ 極の近くのごく短い距離で計算していた。そのため上のくさびの差が数十〜数百倍に拡大され、強い放射状の筋になっていた。光の向きも緯度経度の座標系で決めていたので、極のまわりで回転していた。 |
| テクスチャ | 2048×1024 の正距円筒図を球に貼っていたので、極の近くでは狭い円に1行ぶんの画素が詰まり、筋のようなぼけ（放射状のにじみ）が出ていた。 |
| 球体メッシュ | 極の中心の星形・折れ線。三角形の頂点に置いた経度・緯度を三角形の内側で直線的に補間していたため、極の近くではずれる。同じ理由で、中緯度でも植生のマスが最大約0.1〜0.2°ずれていた（0.5°セルの中心と縁で確認）。 |

**変更**（`app.js`。推定値は変えていない）
1. 地図画像を作ってから貼るのをやめた。画面の各画素が、自分の3次元の向きから経度・緯度を計算し、データの格子を直接読む（GPUで計算）。これで、メッシュの補間による星形・ずれと、正距円筒図の極での詰め込みがなくなった。
2. 陰影は、岩盤のセルごとの法線を3次元（物体座標）で持つ。東西の傾きは、南北のセル間隔とほぼ同じ実距離で取る。光は画面に対して固定の向き（左上から38°、本体アプリと同じ）で、極のまわりで回転しない。
3. 連続量（岩盤・気温・湿度・降水・氷厚）は、各行を約 1/cos(緯度) セル（奇数幅）で平均し、東西と南北がほぼ同じ幅の範囲の値にしてから描く。全行・全項目に同じ式を当てるので、地名別・地域別の補正ではない。緯度約70°より低い所では幅1セルで、何も変わらない。植生の分類は平均しない。中央の値表示も、描画と同じこの値を読む。
4. 海岸線は岩盤を双線形補間した 0 m の等値線、氷の縁は氷厚の 10 m の等値線として、画素ごとに約1画素幅で描く（以前は 0.25° のセルの階段）。植生は 0.5° のセルのまま（分類なので補間しない）。

**解像度について**：以前は 2048×1024 の地図画像（約20 km/画素）を経由していたため、どの倍率でも画像の粗さと階段・にじみで見た目が決まっていた。今は画面の画素ごとにデータを読むので、見た目を制限するのは**元データの格子**（岩盤 0.25°≈28 km、氷・植生 0.5°≈55 km、気温・湿度・降水 2°≈220 km）だけになった。補間は同じ格子の値の間をなめらかにつないでいるだけで、**元データより細かい情報は増えていない**。

**速度**（ソフトウェア描画での比較。実機のGPUでは差はもっと小さいはず）
- 読み込み：2.3〜2.5 秒 → 0.44〜0.58 秒。
- 段階や表示の切替：再描画に 1.1〜1.5 秒 → 次の1フレームで反映。
- 1フレームの負荷：画素ごとの計算が増えたぶん、ソフトウェア描画では 8.0 → 6.3〜6.7 fps。実機のGPUでは1画素あたり約20回のデータ参照で、負荷は小さい見込み。
